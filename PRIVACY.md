# Privacy

**Private conversations. Nothing kept.**

Sotto is designed so that the operator of the deployment cannot read message
content and has nothing to hand over after a conversation ends. This page
describes exactly what is and is not collected.

Sotto is open-source software. The person or organization running a deployment
(the "operator") is the data controller for that deployment. If you are using
someone else's Sotto instance, contact that operator for privacy requests. The
project's security contact is described in [SECURITY.md](SECURITY.md).

## The short version

- Messages, captions, file names, and file contents are **never written to the
  database or file storage**.
- Messages and files disappear from the app after **two minutes**.
- The server stores account details and conversation metadata so that people can
  find each other and exchange encrypted keys.
- There are no analytics, advertising SDKs, trackers, third-party fonts, or
  social embeds.

## What is stored on the server

### Account data (Supabase Auth and `profiles`)

- Email address (used for sign-in, confirmation, and password reset)
- Username (unique and immutable)
- Display name
- Public encryption and signing keys
- Account creation and update timestamps

Passwords are hashed by Supabase Auth; Sotto never sees them in plain text. Email
addresses are visible to the operator in the Supabase dashboard and may appear in
authentication logs.

### Conversation metadata

- Conversation ID, type (direct or group), and group title
- Membership list, roles (admin/member), and join times
- Conversation creation time and creator
- Last activity derived from messages in the open session (in memory only)
- One wrapped copy of the conversation key per member, plus the wrapping
  sender's public key and update time

Wrapped keys are encrypted with keys derived from the members' device keys. The
server cannot unwrap them.

### Abuse prevention

- A blocklist of disposable email domains
- Authentication and database logs generated by Supabase (sign-in attempts, API
  requests, errors) according to the project's logging settings
- Standard hosting logs generated by Vercel (IP address, user agent, requested
  URL, timestamps) according to the Vercel plan and configuration

## What is not stored

- Message text
- File contents, file names, captions, or thumbnails
- Message timestamps in any message table (there is no message table)
- Read receipts, typing indicators, or presence history
- Contact lists, address books, or phone numbers
- Payment data
- Location data
- Advertising identifiers
- Usage analytics

Messages and files exist only in the memory of the connected browsers and as
transient Realtime broadcast frames. The database stores no copy. If a recipient
is offline, the message is not delivered and cannot be recovered later.

## Data stored on your device

| Storage      | Contents                                                 | Lifetime                                        |
| ------------ | -------------------------------------------------------- | ----------------------------------------------- |
| IndexedDB    | Device private keys (ECDH and ECDSA JWKs), origin-scoped | Until site data is cleared                      |
| localStorage | Supabase session token, theme preference                 | Until sign-out, expiry, or site data is cleared |
| Memory       | Decrypted messages, attachments, conversation keys       | Up to 2 minutes / until the tab closes          |
| Blob URLs    | Downloadable copies of received files in memory          | Revoked at TTL expiry or unmount                |

Signing out clears the Supabase session but intentionally keeps the device
identity, so signing back in on the same browser retains the same keys. Use
**Delete account** in Settings to remove the server account and local data; use
your browser's "clear site data" option to remove the local identity without
deleting the account.

## Why metadata exists

End-to-end encryption protects content, not the fact that two accounts are in a
conversation. Supabase must know which accounts may join which Realtime channel,
which public keys belong to whom, and which wrapped key belongs to which member.
That requires account and membership records.

Metadata can reveal who talks to whom, when a conversation was created, group
size, and traffic volume. Sotto does not attempt to hide this from the operator.

## Sharing with third parties

Sotto does not sell data and has no advertising partners. A deployment typically
uses:

- **Supabase** for authentication, Postgres, and Realtime. Data is processed in
  the region selected by the operator.
- **Vercel** for static hosting and edge delivery.
- **An email provider** chosen by the operator (Supabase's mailer or custom SMTP)
  to deliver confirmation and password-reset messages. That provider sees the
  recipient's email address and the message contents.
- **A TURN provider**, if configured, which relays encrypted WebRTC media. It can
  see IP addresses and traffic volume, but not decrypted audio or video.

Each provider processes data under its own terms and privacy policy. The
operator is responsible for choosing providers, regions, and retention settings.

## Retention and deletion

- **Messages and files:** at most two minutes in browser memory, then gone.
- **Account and profile data:** until the account is deleted.
- **Conversation metadata:** until the conversation is deleted, the account is
  deleted, or the last member leaves.
- **Wrapped keys:** until membership changes, the account is deleted, or the
  conversation is deleted.
- **Supabase and Vercel logs:** according to the retention configured by the
  operator (often 7–30 days; check the project settings).
- **Backups:** may retain metadata for the backup window configured by the
  operator. Backups never contain messages.

Deleting an account through Settings removes the auth user and cascades profile,
membership, and key rows. Group admin roles are transferred to another member;
direct messages are deleted. Some provider logs and backups may persist for their
configured retention period. Deleting the account cannot recall content that
another person already received, saved, or screenshotted.

## Your choices and rights

Depending on where you live, you may have rights to access, correct, export, or
delete personal data, object to processing, or lodge a complaint with a
supervisory authority. For a Sotto deployment:

- You can edit your display name in Settings.
- You can delete your account in Settings.
- You can request metadata access or erasure from the deployment operator.
- You can clear local keys and session data in your browser at any time.

Because message content is never stored, the operator cannot export or delete
message history — there is none to export or delete.

## Children

Sotto is not directed at children and is not intended for anyone below the age
required to consent to data processing in their jurisdiction. Operators should
set and enforce an appropriate minimum age.

## International transfers

Data location depends on the Supabase region, Vercel edge configuration, SMTP
provider, and TURN provider selected by the operator. Operators are responsible
for transfer safeguards required by applicable law.

## Changes

This document may change as the software evolves. Material changes should be
noted in the repository history and, for a deployed service, communicated by the
operator. The software version in `package.json` identifies the release.
